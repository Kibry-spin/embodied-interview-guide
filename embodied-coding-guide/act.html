01 · ELEVATOR PITCH

面试先答这一分钟

60 秒回答

ACT 全称 Action Chunking with Transformers，是一种端到端行为克隆策略。普通 BC 每次只预测一个动作，长任务容易因为小误差进入训练集之外的状态；ACT 从当前多相机图像和机器人本体状态一次预测未来 k 步动作，使策略直接学习一段具有时序一致性的运动，概念上把有效决策时域缩短约 k 倍。架构上，训练阶段先用一个 Transformer VAE encoder 读取 [CLS]、当前关节状态和未来动作序列，得到动作风格分布 μ、logσ²，并通过重参数化得到 z；主策略再用 ResNet 提取图像特征，将视觉 token、本体 token 和 z 编码为 memory，DETR 风格 decoder 用 k 个可学习 Action Query 并行回归整个动作块。损失是有效动作位置上的 L1 重建误差加 β 倍 KL 散度。推理时没有真值动作，原版与 LeRobot 实现都令 z=0；可以一次执行若干动作后重规划，也可以每步重新预测并对重叠 chunk 做 Temporal Ensemble。

一句话

ACT = Action Chunk 解决长时误差累积，CVAE 表达示范风格，DETR Query 并行生成未来动作，Temporal Ensemble 平滑重叠预测。

02 · MOTIVATION

为什么单步行为克隆不够

ACT 的每个组件都在对应一个真实数据问题，而不是为了堆模型。

ONE-STEP BC

π(ot) → at

每一步独立回归。一个很小的动作误差改变下一时刻观测，随后模型在训练分布之外继续预测，误差可能逐步放大。

  • 优点：实现简单、响应新观测快
  • 问题：缺少动作段的整体结构
  • 高频暂停等示范噪声容易被逐步复制
ACTION CHUNKING

π(ot) → at:t+k−1

一次预测一段未来动作，模型直接学习动作之间的相关性。若整段执行，长度为 T 的任务只需约 T/k 次策略决策。

  • 优点：动作一致、推理频率可降低
  • 代价：chunk 内对环境变化反应变慢
  • 需要决定何时重规划与如何衔接
01 · COMPOUNDING ERROR误差累积

监督学习只覆盖专家状态分布；部署后自己的动作会改变后续输入分布。

02 · TEMPORAL CORRELATION时序混杂

人的停顿、犹豫与速度变化具有连续相关性，单步 Markov 回归很难区分。

03 · MULTIMODAL DEMOS多种可行动作

同一观测下可能左绕或右绕；直接回归平均动作可能落入任何示范都没有的区域。

严谨表达

“有效时域缩短 k 倍”最适用于预测并执行完整 chunk 的解释。开启 Temporal Ensemble 后模型每个控制步都会重新查询，此时主要收益变为结构化预测与重叠集成，而不是减少 forward 次数。

为什么 ACT 不是强化学习？

训练目标没有奖励、价值函数或策略梯度，只是在专家数据上最小化动作重建误差与 KL 正则。真机 rollout 用于评测，不会自动产生训练信号。

Action Chunk 能彻底解决分布偏移吗？

不能。它减少策略重新决策的次数并提供局部时序结构，但错误 chunk 仍可能把机器人带到未见状态。真正补齐分布需要纠错示范、DAgger、干预数据或在线微调。

为什么不能只看 validation L1？

离线误差是在专家分布上计算，且每个动作维度平均后会掩盖关键接触阶段。最终应以闭环任务成功率、轨迹平滑度、接触质量和恢复能力评估。

你的遥操作数据如何适配 ACT？

先确保 observation 与 action 的时钟、坐标系、语义和控制频率一致，再在 episode 内构造未来窗口。多设备来源应分别检查延迟和动作分布，不能只完成格式转换。

面试主线

先说 ACT 是 chunk-level behavior cloning，再解释它用 Action Chunk 降低有效时域、用 CVAE 表达示范风格、用 Temporal Ensemble 平滑重叠预测；最后主动指出它仍受数据覆盖和 covariate shift 限制。

CHUNK SIZE · k

预测多远

模型每次输出的动作长度。控制频率为 f 时，对应物理时长约 k/f 秒。

ACTION STEPS · e

实际执行多少

队列模式只执行前 e 步再重规划，要求 1 ≤ e ≤ k；其余预测丢弃。

QUERY RATE

多久重新推理

Temporal Ensemble 通常每步 query；普通队列每 e 步 query，响应性与算力开销不同。

例子

50 Hz 控制、k=100 表示模型看未来约 2 秒；若 n_action_steps=25，则执行 0.5 秒后重规划，并不是一定开环执行 2 秒。

06 · CONDITIONAL VAE

z 不是随机噪声，而是动作风格

例如不同示范者的速度、停顿、接近方向和双臂配合方式。

POSTERIOR INPUT[CLS], qt, At:t+k−1训练阶段能够看到未来示范
→
VAE ENCODERμ, logσ²描述动作风格分布
→
REPARAMETERIZEz = μ + σ ⊙ εε ~ N(0,I)，梯度可回传
→
POLICYÂ = π(ot,qt,z)重建未来动作块
qφ(z | qt, At:t+k−1)　≈　N(μ, diag(σ²))，　p(z)=N(0,I)
训练时看未来动作，算数据泄漏吗？

不算。未来动作只进入训练期 posterior，用来推断这一条示范的 latent 风格；部署时该分支被移除，策略只依赖当前观测、本体状态和先验 latent。它与 VAE 训练时用 x 推断 z、生成时从 prior 取 z 是同一种结构。

为什么需要 KL？

只做重建时，posterior 可以把每条动作序列编码到任意离散位置，推理时从标准高斯或零点取 z 会落在模型没见过的区域。KL 把 qφ 拉向 N(0,I)，让训练与推理 latent 空间接轨。

推理时 z 怎么来？

原版 ACT 和 LeRobot 实现都直接使用全零 latent，也就是 prior 的中心，得到稳定、确定性的“平均风格”。理论上可以从 N(0,I) 采样获得多样动作，但真机控制通常更看重可重复性。

什么是 Posterior Collapse？

若 KL 权重过强或 decoder 太强，q(z|·) 被压成先验，模型忽略 z，μ≈0、logσ²≈0。要同时监控重建误差、KL、latent 方差和不同 z 下的输出差异。

代码级纠正

不要只背“推理时从 prior 采样”。官方实现实际上创建全零 latent；如果你的实现改成随机采样，要明确这是部署策略的改变，并验证随机性是否导致真机轨迹不稳定。

→
LINEAR HEADât, ât+1, …

每个 decoder token 经过同一个线性层映射到 Da 维连续动作。

问题正确理解
Action Query 是动作 token 吗？不是。它首先是“第几个未来槽位”的可学习 embedding，经 decoder 读 observation memory 后才变成动作表示。
ACT 是自回归生成吗？不是。k 个 query 在一次 forward 中并行输出；动作时间维内部可以双向 self-attention，不需要 causal mask。
为什么不直接用一个 MLP 输出 k×Dₐ？Query 提供显式时间槽，decoder self-attention 建模未来动作之间的依赖，cross-attention 允许每个时间槽选择不同视觉区域。
多相机如何融合？原实现对每路图像提特征后沿空间维拼接，再与对应位置编码一起送入 Transformer；LeRobot 版本将各相机二维特征展平成 token 序列。

08 · TRAINING OBJECTIVE

重建动作，同时约束 latent

LACT = L1, valid(A, Â) + β · DKL(qφ(z|q,A) || N(0,I))
RECONSTRUCTION

Masked L1

只计算 episode 内真实存在的动作。L1 直接监督每个时间步、每个动作维度的连续回归误差。

Σ |a−â| · valid / Σ valid
REGULARIZATION

KL Divergence

让 posterior 接近标准高斯，使部署时 z=0 位于训练过的 latent 区域。

−½Σ(1+logσ²−μ²−exp(logσ²))
def act_loss(actions_hat, actions, is_pad, mu, logvar, beta=10.0):
    # actions_hat/actions: [B, k, Da], is_pad: [B, k]
    valid = (~is_pad).unsqueeze(-1)                    # [B, k, 1]
    abs_err = (actions_hat - actions).abs()
    denom = (valid.sum() * actions.size(-1)).clamp_min(1)
    l1 = (abs_err * valid).sum() / denom

    kl_per_sample = -0.5 * (
        1 + logvar - mu.square() - logvar.exp()
    ).sum(dim=-1)                                      # [B]
    kl = kl_per_sample.mean()
    return l1 + beta * kl, {"l1": l1, "kl": kl}
β TOO SMALL

训练好，推理差

posterior 任意编码示范，z=0 可能落在空洞区域；KL 大、latent 分布分散。

β TOO LARGE

忽略动作风格

posterior collapse，重建变差；不同动作模式被压成接近相同输出。

PAD MASK

末尾不能凑零训练

必须把补齐位置从 L1 和 VAE encoder attention 中同时屏蔽。

面试对比

ACT 用直接 L1 回归完整动作块；Diffusion/Flow Policy 通常对噪声或速度做 MSE，并需要多步数值采样。不要把 ACT 的 z 和 diffusion noise 混为一谈。

def build_act_sample(episode, t, chunk_size):
    obs = episode["observation"][t]
    end = min(t + chunk_size, len(episode["action"]))
    valid_len = end - t

    chunk = zeros(chunk_size, action_dim)
    chunk[:valid_len] = episode["action"][t:end]
    is_pad = ones(chunk_size, dtype=bool)
    is_pad[:valid_len] = False
    return obs, chunk, is_pad

def select_action(obs):
    if len(action_queue) == 0:
        chunk = policy.predict_action_chunk(obs)       # [B, k, Da]

e = n_action_steps反馈响应推理成本适合场景
e = k最慢，整个 chunk 近似开环最低环境稳定、动作节奏固定

先用任务事件持续时间确定 k，再根据环境变化速度和模型延迟选择 e。接触前后应更频繁重规划；自由空间大范围运动可以执行更长前缀。

11 · TEMPORAL ENSEMBLE

同一个当前动作，会被多个 chunk 预测

每一步都 query，新旧 chunk 在绝对时间轴上重叠。

QUERYt−3 t−2 t−1 t ABSOLUTE STEP →　t−2　t−1　t　t+1　t+2
at = Σj wj ât(j)，　wj = exp(−m·j) / Σ exp(−m·j)
WHY IT WORKS

重叠预测降噪

每个 chunk 对同一绝对时间 t 给出一个估计。加权平均降低相邻 query 的偶然抖动，使 chunk 交界更连续。

THE TRADE-OFF

平滑与响应性

更信任旧预测会更稳定，但可能忽略刚出现的新视觉或触觉变化；更信任新预测响应快，但 chunk 结构可能被频繁打断。

高频陷阱

LeRobot 的定义中 w₀ 对应最旧预测。m>0 时权重随索引下降，因此较旧预测权重更高；m=0 是均匀平均；m<0 才更偏向新预测。原论文/实现常用 m=0.01。不要凭直觉说成“默认更相信最新观测”。

# 概念版：all_preds[j] 都在预测同一个绝对时刻 t 的动作
weights = torch.exp(-m * torch.arange(len(all_preds), device=device))
weights = weights / weights.sum()
action_t = (torch.stack(all_preds) * weights[:, None]).sum(dim=0)
与 RTC 区别

Temporal Ensemble 是输出后平均多个完整预测；RTC 在生成新 chunk 时把旧 chunk 前缀作为约束或条件，处理异步延迟和“已经来不及修改”的动作。两者都解决衔接，但机制不同。

为什么 ACT 仍是重要 baseline？

它训练稳定、推理一次完成、数据接口清晰，而且 Action Chunking 本身非常有效。复杂生成模型必须在相同数据、观测、执行 horizon 和评测协议下显著超过 ACT，改进才有说服力。

ACT 与 VLA 是竞争关系吗？

不一定。ACT 更像低层 visuomotor policy；VLA 负责语言理解、跨任务语义和大规模先验。VLA 可以采用 action chunk decoder，也可以把 ACT 作为单任务专家或低延迟执行器。

ACT 与 RTC 的关系？

ACT 提出了 chunk 与 overlap；RTC 进一步面向慢速大模型的实时异步执行，让新 chunk 在已经承诺的动作前缀后平滑续写。RTC 不是 ACT 必需组件，但解决了更严格的推理延迟问题。

什么时候优先选 ACT？

数据量有限、任务相对单一、动作维度中等、要求低延迟并需要快速建立可靠 baseline 时。若示范存在强多模态且平均动作不可行，再比较 Diffusion/Flow。

16 · INTERVIEW Q&A

必须能连续追答

Q1：ACT 为什么能缓解 compounding error？

它一次预测 k 步，使一段运动作为整体学习；若执行完整 chunk，策略决策次数从约 T 降到 T/k。即使每步重规划，chunk supervision 也提供未来结构。但它不能消除分布偏移，仍依赖高质量示范和闭环重规划。

Q2：CVAE 解决的是什么问题？

示范在相同观测下可能存在多种合理动作风格。posterior 从真值动作提取 z，decoder 在 z 条件下重建对应模式；KL 让 latent 接近可部署的标准先验。

Q3：为什么推理时不需要 VAE Encoder？

它的输入包含未来真值动作，部署时不存在。训练通过 KL 让 posterior 靠近 N(0,I)，因此推理只需从 prior 选 z；原实现为稳定性直接取 z=0。

Q4：k 个 Action Query 在做什么？

每个 query 是一个未来相对时间槽，通过 decoder self-attention 协调动作段内部关系，再 cross-attend observation memory，最后映射到连续动作。它们不是历史动作，也不是自回归 token。

Q5：ACT 的 decoder 需要 causal mask 吗？

不需要。完整未来 chunk 在一次 forward 中并行预测，每个时间槽可以看到其他 query 表示；causal mask 是自回归生成时防止看未来的要求。

Q6：chunk_size 越大越好吗？

不是。大 k 增强长时一致性并摊薄推理，但远期动作不确定性更高、接触变化时反应更慢、训练 padding 更多。应结合控制频率、任务子阶段和执行 horizon 选择。

Q7：Temporal Ensemble 为什么平滑？

当前绝对时间的动作由多个过去 query 产生的重叠预测共同估计，加权平均降低单次 chunk 波动。但它也可能稀释最新反馈，因此权重方向和系数需要实机验证。

Q8：ACT 与 Diffusion Policy 最大差异？

ACT 用 CVAE latent 条件下一次直接 L1 回归动作块；Diffusion Policy 从随机噪声经过多步去噪得到动作块。ACT 延迟低，Diffusion 对复杂多峰分布通常更有表达力。

Q9：为什么训练 loss 平台后继续训练可能仍有收益？

平均 L1 的微小变化不一定反映闭环轨迹质量；长训练可能继续改善动作段的相位、一致性与平滑度。官方仓库也提示真机任务的成功率和流畅度可能在 loss 平台后继续提升，所以必须看 rollout。

Q10：怎样给 ACT 加触觉？

先根据触觉类型设计 encoder：图像式触觉保留空间 token，低维力/接触量可编码成全局或时间窗口 token，再与视觉、本体一起进入 policy encoder。关键是对齐时间、标定量纲并设计缺失模态策略。

17 · ACTIVE RECALL

用六道题检查是否真正理解

1. ACT 的主要输出是什么？

答案：输出 [B,k,Dₐ] 连续动作序列。

2. 训练期 VAE Encoder 的输入包含什么？

答案：posterior 需要从未来示范提取动作风格。

3. 原版 ACT 推理时 latent z 如何设置？

答案：官方代码和 LeRobot 都用零 latent。

4. 哪个位置必须使用 padding mask？

答案：补齐动作既不能影响 posterior，也不能进入重建损失。

5. LeRobot Temporal Ensemble 中 m>0 默认更偏向谁？

答案：w₀ 对应最旧预测，正 m 使后续权重递减。

6. ACT 的 Action Query 是否需要 causal mask？

答案：ACT 不是沿动作时间自回归生成。
