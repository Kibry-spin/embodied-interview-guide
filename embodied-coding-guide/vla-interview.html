01 · ELEVATOR PITCH

30 秒先讲清楚

推荐回答

VLA 是把视觉观测、语言任务和机器人自身状态映射为动作的多模态策略。典型系统用视觉编码器提取场景和物体特征，用语言模型或 Transformer 提供语义理解与时序建模，通过 projector、cross-attention 或条件调制完成融合，最后由动作头输出离散 action token、连续动作或动作 chunk。与普通 VLM 相比，关键新增了本体状态、动作空间、时间对齐和闭环控制。

不要把 VLA 与某一种固定网络结构画等号

RT-1、RT-2、OpenVLA 与 π 系列在视觉骨干、语言主干和动作解码方式上均不同。面试中应先讲通用模块，再举具体模型。

四层架构：输入、编码、融合、动作

01 / INPUT
多模态历史观测

多路 RGB/RGB-D、语言指令、本体状态，可选触觉、力觉和环境状态；首先完成时间同步。

[B,S,...]
02 / ENCODER
模态专用编码器

ViT/CNN 将图像变为视觉 token；Tokenizer + LLM 表示任务；MLP 将低维状态投影到共享维度。

tokens / features
03 / FUSION
跨模态条件建模

通过 token 拼接、cross-attention、FiLM/AdaLN 或晚期拼接，让动作查询获得场景、任务和机器人状态。

c = f(v,l,s)
04 / POLICY
时序骨干与动作头

Transformer、RNN 或 DiT 建模时间关系；动作头选择离散 token、连续回归、diffusion/flow 等输出形式。

[B,H,Da]
05 / CONTROL
反归一化与闭环执行

转换到机器人控制坐标系，进行安全裁剪、频率匹配和动作队列执行，再用新观测重新规划。

at → robot
VISION回答“看到了什么”

场景布局、物体类别、几何关系和接触前视觉信息。

LANGUAGE回答“要做什么”

任务语义、目标物体、约束和可复用的先验知识。

PROPRIO回答“机器人现在怎样”

关节、末端、夹爪和历史动作决定动作是否可执行。

04 · MULTIMODAL FUSION

多路信息怎样进入模型

融合不只是 torch.cat；必须同时处理表示维度、采样频率、缺帧和不同坐标系。

[visual tokens; language tokens; state tokens; action queries]
优势

统一建模

所有 token 在同一 Transformer 内交互，表达能力强，结构直观。

代价

序列变长

注意力成本随 token 数平方增长，还需明确位置与模态编码。

Q = action/state tokens,   K/V = vision-language context

动作查询主动从条件 token 中读取相关信息，适合把强大的预训练 VLM 作为上下文编码器；Q 与 K/V 的序列长度可以不同。

h′ = γ(c) ⊙ Norm(h) + β(c)

FiLM 或 AdaLN 用条件生成 scale/shift/gate，不必把条件扩成大量 token。RT-1 使用语言条件调制视觉特征；DiT/Flow 策略也常用 AdaLN。

c = concat(flatten(vision), state, tactile, ...)

实现简单、算力可控，常见于中小型机器人策略；缺点是细粒度 token 交互较弱，且展平会丢失部分空间结构。

加入触觉时怎么回答

先按传感器特性编码触觉，再与视觉、本体状态按时间戳对齐；触觉可作为独立 token、全局条件或反馈状态进入动作头。真正的难点是触觉接触稀疏、尺度归一化和视觉—触觉—动作延迟，而不是单纯增加一个输入键。

05 · LONG-HORIZON MODELING

Transformer vs RNN 怎么选

长时域任务通常还需要层级规划、记忆或动作 chunk，不能只靠无限增加序列长度。

维度TransformerRNN / LSTM / GRU选择建议
依赖建模任意 token 直接交互，长距离路径短信息递归压入 hidden state复杂多模态与长依赖优先 Transformer
并行训练序列维可并行时间维串行大规模离线训练 Transformer 更友好
计算/内存标准 attention 为 O(L²)随序列线性增长，hidden 固定低算力、流式控制可考虑 RNN
在线状态需窗口或 KV Cache天然维护递归状态超低延迟控制 RNN 更简单
可扩展性易融合语言、图像和动作 token多模态扩展通常更定制VLA 主干通常偏向 Transformer
HIGH LEVEL任务分解

语言/VLM 预测子任务或技能序列，降低低层策略的时域压力。

LOW LEVELAction Chunk

一次生成短动作序列，兼顾平滑性与推理频率。

MEMORY历史与状态

显式缓存关键事件、对象状态，避免固定窗口遗忘。

CONTROL滚动重规划

只执行 chunk 的前 K 步，再根据最新观测更新。

推荐表达

如果任务依赖多模态语义和较长历史，我优先用 Transformer；如果硬件算力有限、控制频率高且有效状态可压缩，RNN 更轻量。真正的长任务通常采用“高层子任务规划 + 低层动作 chunk + 闭环重规划”，而不是只在二者中二选一。

06 · MODEL LANDSCAPE

π、RT、OpenVLA 放在一张表里

面试重点不是背参数量，而是讲清预训练来源、动作表示与工程取舍。

模型骨干与融合动作输出核心特点适合怎样回答
RT-1EfficientNet + 语言 FiLM + TokenLearner + Transformer离散动作 token，逐步控制面向多任务真机数据，强调高效实时控制与规模化训练“早期可扩展机器人 Transformer，动作离散化”
RT-2PaLI-X / PaLM-E 等预训练 VLM 与机器人数据协同微调把动作表示成文本式 token 序列把 Web 语义知识迁移到控制，增强新指令和语义推理“从 VLM 直接输出动作 token 的代表”
OpenVLADINOv2 + SigLIP 视觉骨干，Llama-2 语言主干离散化 7-DoF 动作7B 开源 VLA，提供推理、LoRA 与全参微调工具链“适合研究复现和新任务适配”
π₀预训练 VLM + 独立 action expertFlow Matching 连续高频动作 chunk避免纯自回归动作 token 在高频灵巧控制中的限制“语义 VLM 与连续生成式动作头结合”
π₀.₅延续 VLM/动作专家并进行多来源协同训练连续动作，并结合高层语义预测利用跨机器人数据、Web/语义任务与人类高层指令，面向新环境长任务“重点是异构数据协同和开放世界泛化”
比较时不要只说“新模型效果更好”

应围绕三条轴：动作是离散 token 还是连续生成；是否复用 Web 预训练语义；是否面向实时高频动作、跨机器人或开放环境泛化。

07 · ACTION SPACE

动作空间设计决定策略学什么

回答时至少说明控制对象、坐标系、绝对/增量、旋转表示、频率和归一化。

at = [Δx, Δy, Δz, Δrx, Δry, Δrz, gripper]
END-EFFECTOR

笛卡尔空间

位置 + 姿态 + 夹爪，跨机械臂更直观；需要 IK 或底层控制器执行。

JOINT

关节空间

关节位置、速度或力矩，执行直接；与具体本体绑定更强。

MOBILE / BIMANUAL

组合动作

双臂、灵巧手、移动底盘维度拼接，并额外处理异步频率和 mask。

设计项常见选择需要说明的取舍
绝对 vs 增量目标 pose / Δpose增量更局部稳健，绝对目标更依赖标定但误差不易累积
坐标系base / world / camera / gripper必须与数据采集、训练和部署一致；跨本体常用 gripper-relative
旋转表示Euler、axis-angle、quaternion、6D注意奇异性、归一化与连续性；损失不能盲目逐维 MSE
夹爪二值、开合量、速度或多关节手势离散动作和连续动作的 loss/后处理不同
频率与 chunk单步 / H 步动作块控制频率、推理延迟与反馈新鲜度共同决定执行 K
结合项目回答

我会先统一机器人、相机与遥操作设备的坐标系，再明确动作是末端增量还是关节目标，并记录控制频率和时间戳；训练前依据统计量归一化，部署时反归一化、限幅并做安全检查。动作维度本身不难，最容易出错的是语义和坐标系在采集、训练、推理之间不一致。

08 · FINETUNING & POST-TRAINING

微调不是只在 LoRA 和全参中二选一

先明确要适配的是视觉域、语言语义、动作空间还是机器人动力学，再决定哪些模块需要更新。

W′ = W + ΔW,   ΔW = (α/r)BA
A∈Rr×din, B∈Rdout×r, r ≪ d
minimal_lora_linear.py
class LoRALinear(nn.Module):
    def __init__(self, base, rank=8, alpha=16):
        super().__init__()
        self.base = base
        for p in self.base.parameters():
            p.requires_grad = False

        self.A = nn.Parameter(torch.randn(rank, base.in_features) * 0.01)
        self.B = nn.Parameter(torch.zeros(base.out_features, rank))
        self.scale = alpha / rank

    def forward(self, x):
        base_out = self.base(x)
        lora_out = (x @ self.A.T) @ self.B.T
        return base_out + self.scale * lora_out
维度LoRA全参数微调
训练参数与显存少，优化器状态显著降低；适合单机/少卡大，通常需要分布式与更高显存
适配能力适合相近域、新任务和小中型数据分布变化大、需要重塑底层表征时上限更高
过拟合风险相对较低，保留预训练能力较好小数据下更容易破坏通用表征
部署管理基座 + 多个小 adapter，可合并权重每个任务保存完整模型
VLA 实践常加在 LLM attention/MLP，动作头可单独训练数据充足且本体/视觉域差异很大时考虑
什么时候从 LoRA 升级到全参？

先用 LoRA 建立低成本基线。如果新相机视角、本体动作语义或任务分布与预训练差异很大，而且 LoRA 明显欠拟合，同时有足够数据与算力，再考虑解冻视觉编码器、动作头或全模型。选择依据是域差异、数据规模和算力，不是模型越大越应全参。

TRAINING LADDER

BC、生成式策略与 RL 怎样衔接

阶段解决什么典型做法不要混淆
Behavior Cloning用专家演示建立可用初始策略连续回归、ACT、Diffusion/Flow 都可以在示范数据上做监督模仿Diffusion/Flow 是动作分布参数化，不代表已经做了 RL
生成式 Action Head表达连续、高维、多峰 action chunkCVAE、Diffusion、Flow Matching能表达多峰不等于解决 covariate shift
DAgger / 纠错数据补充策略偏离专家分布后遇到的状态人工接管、恢复示范、失败后重试轨迹需要安全的数据采集协议与清晰的专家标签
Offline RL / 加权 BC利用成功、失败和质量不同的离线轨迹return/advantage weighting、保守价值学习离线价值外推误差可能把策略推向数据外动作
Online RL / Preference针对任务奖励、恢复与人类偏好继续优化安全 rollout、奖励模型或偏好优化真机采样昂贵且危险，必须有限幅、回退和固定评测
灾难性遗忘怎么回答

先建立旧能力回归集，而不是只看新任务成功率；训练时可冻结主干或用 LoRA、降低 VLM 学习率、混入一部分通用/旧任务数据并控制采样权重。若动作损失需要更新 VLM，应明确梯度范围；attention mask 控制前向可见性，不等于 stop-gradient。

贴合你的下一步实验

可以在同一 LeRobot 小数据集上比较 MSE/ACT/Flow 的动作质量，再定向加入 QTac 的调整示范或遥操作纠错段，观察任务成功率、数量误差、chunk 接缝 jerk 和恢复率。它比声称“完成大模型 RLHF”更可信，也更贴合现有经历。

DATA DIVERSITY

数据多样性不足会怎样

SHORTCUT学习场景捷径

把背景、固定位置或操作者特征误当成任务线索。

SHIFT分布外失效

光照、物体、相机、本体或动作初态变化后性能骤降。

IMBALANCE长尾技能被淹没

高频 pick-place 主导损失，稀有纠错和接触行为学不到。

CLOSED LOOP不会恢复

只有成功示范、缺少偏离与纠错数据，部署时误差不断累积。

如何提高多样性

从任务、物体、场景、相机、初始状态、操作者、本体和成功/失败模式分层覆盖；训练采样时控制任务权重；保留纠错轨迹并建立独立 OOD 测试集。数据量很重要，但覆盖边界和动作质量同样重要。

12 · SIM2REAL

Reality Gap 分成六类回答

Sim2Real 的核心不是让仿真“完全真实”，而是让策略在一组可能环境中学到稳健行为。

VISUAL

视觉差异

纹理、光照、阴影、背景、相机噪声、曝光和分辨率。

GEOMETRY

几何与标定

物体尺寸、相机内外参、机器人零位与坐标变换误差。

DYNAMICS

动力学

质量、惯量、电机响应、阻尼、控制增益和通信延迟。

CONTACT

接触与材料

摩擦、刚度、形变、碰撞求解与触觉/力觉响应最难精确模拟。

SENSOR

观测噪声

延迟、丢帧、漂移、遮挡和多传感器不同步。

TASK

任务分布

初始状态、物体组合、干扰物和人类行为超出仿真覆盖。

θ ~ p(θ),   maximize Eθ[J(π;θ)]
Domain Randomization 的核心

训练时随机化纹理、光照、相机、质量、摩擦、延迟、控制增益和初始状态，让真实世界成为训练分布中的一种可能情况。范围过窄覆盖不了真机，过宽且不合理则会增加学习难度，因此最好结合系统辨识确定中心和范围。

SIM + REAL

仿真与真机数据怎样混用

01仿真预训练 → 真机微调

先学视觉/几何或基础动作，再用少量高质量真机数据校准观测和动力学分布。

02联合采样训练

在同一 batch 或交替 batch 中混合来源，用采样权重防止大量仿真数据淹没真机信号。

03共享主干 + 域专用模块

共享语义/策略表示，为 sim/real 使用域标记、独立归一化或小型 adapter。

04真机闭环校准

在安全范围收集 rollout、失败和纠错数据，迭代修正仿真无法覆盖的接触与延迟。

推荐工程回答

我会先保证 sim 和 real 的 observation/action schema、坐标系和频率一致，再做视觉与动力学随机化；训练上先仿真预训练，再用真机数据微调或加权联合训练；评估时分开报告仿真、真机 ID 和真机 OOD，最终以真实闭环任务成功率和失败类型为准。

VLM-as-a-Judge 的边界

它可以降低视频语义评审成本，但不能替代机器人状态、接触力、碰撞和精确数量等可测指标。必须先验证 Judge 与人工标注的一致性，并保存判定理由；安全相关结论不能只依赖概率模型。

如何证明触觉真的有用

除了 full model 与 no-tactile ablation，还应打乱触觉时间、交换左右传感器、用错误数量分布做反事实，并分别评测接触前和接触后阶段。如果动作只在正确时序触觉下改善，才更能说明策略使用了触觉信息。

如何避免 benchmark 过拟合

固定任务协议、对象集合和随机种子；开发集与最终真机测试隔离；按物体、场景和 episode 切分而不是随机切帧；报告多个 checkpoint/seed 和失败类别。LIBERO 分数可作算法信号，但不能替代真机系统证据。

ACTION LABEL & DATA SCALE

“关节角还是末端位姿”不能只选一个词

面试追问回答主线工程取舍贴合你的项目
训练标签是什么？先区分原始记录与策略监督：数据最好同时保留关节状态、末端位姿、夹爪/手指状态和 commanded/executed action；真正训练哪一种由 policy config 决定。关节动作执行直接但绑定本体；末端动作更易跨机械臂，但依赖坐标变换、IK 与底层控制器。双臂 Franka + Sharpa 数据要明确左右臂/手字段顺序、绝对或增量动作、参考坐标系和控制频率，不能只回答“14 维”。
为什么常用末端增量？它描述局部任务空间运动，弱化机器人零位与连杆差异，也更接近 UMI/Tracker 的轨迹表示。仍需定义增量相对哪一帧、旋转表示、缩放、action horizon，以及由谁完成 IK。你的 OMMO 手部关键点已统一到相机系；继续映射机器人时还要接 base–camera 外参和 retarget/IK。
训练数据量多大？报告 episode 数、成功时长、控制频率、任务/物体/场景/操作者覆盖，以及训练后可形成的有效窗口数。“十万帧”可能只是高 FPS 重复帧；“几百条轨迹”也可能包含不同长度和质量。必须同时给物理时长与分布。分别报告 QTac 示教、遥操作数据和触觉链路验证数据，不把调试日志或无标签采集都算成有效专家轨迹。
怎样划分数据？以 episode、物体或场景分组切分，窗口只能在所属 split 内生成。逐帧随机划分会让同一条轨迹同时进入训练和验证，造成严重泄漏。QTac 可按已见/未见物体拆分；遥操作平台应另外保留跨操作者、初态和场景测试。

“我使用的是［动作定义与频率］，共［episode 数］条、约［有效时长］小时，覆盖［任务/物体/场景/操作者］；过滤异常与失败标签后生成约［有效窗口数］个训练样本，按［episode/物体/场景］划分训练和测试。这里的数量只统计可训练数据，不把设备调试记录计入。” 数字不确定时回去查 metadata，不要现场估大。

状态与动作小幅传感噪声、起始状态扰动、动作平滑扰动、左右对称任务镜像超过物理可达范围；镜像后未同步旋转、夹爪和语言标签离线检查限位/碰撞，再做闭环鲁棒性和 jerk 回归。
触觉增益/偏置、漂移、噪声、局部 taxel dropout、时间错位、整模态 dropout把真实“无接触零值”和传感器掉线混为同一输入分别测试无接触、缺帧、饱和、滑移和未见材质；输入 validity mask。
语言同义改写、指代变化、长短指令、无关修饰和必要的澄清样本改写改变目标、数量、顺序或左右关系，却仍保留原动作标签建立语义等价组和歧义组，分别测一致性与澄清率。
“用了哪些增强、效果如何”的标准回答

给出 baseline → 单项增强 → 组合增强的受控消融，固定数据划分、训练预算和随机种子；同时报告 ID 与目标 OOD 子集。增强若只提高平均分、却损害精细接触或数量判断，应保留分项结果，而不是笼统称为有效。

MHA CODE REVIEW

写完 MHA 后，面试官通常检查这七件事

01可整除

D % H == 0，每头维度 Dh=D/H。

02拆头顺序

[B,L,D] → [B,H,L,Dh]，不是只 reshape 不 transpose。

03Score shape

Q @ Kᵀ → [B,H,Lq,Lk]。

04缩放位置

softmax 前除以 √Dh。

05Mask 语义

明确 True 是允许还是屏蔽，并能广播到 scores。

06合并 heads

transpose 后用 reshape/contiguous，恢复 [B,Lq,D]。

07Cache 边界

自回归只缓存每层 K/V；新 Query 长度通常为 1，cache 随序列线性增长。

16 · INTERVIEW DRILL

高频追问与回答骨架

问题 1

VLA 与 VLM 的本质区别？

从输入、输出、时间与部署四点回答。

VLM 主要建立图像—文本语义映射；VLA 进一步输入本体/历史状态，输出带坐标系和控制频率定义的机器人动作，并在闭环中持续执行。因此它额外面对时序对齐、动作表示、控制延迟和安全约束。

问题 2

为什么 π₀ 用 Flow Matching？

结合连续动作、多模态分布和高频 chunk。

Flow Matching 可直接生成连续动作 chunk，避免逐维离散 token 的量化和自回归延迟；从随机噪声还能表达同一条件下多种合理动作模式，适合高频、灵巧的连续控制。

问题 3

LoRA 微调后效果差怎么办？

不要只回答“提高 rank”。

先检查数据语义、归一化与动作坐标；再调整 adapter 位置、rank、学习率和训练动作头；若视觉/本体域差异大，可逐步解冻 projector、视觉后层或动作专家。数据充足且仍欠拟合时再考虑全参。

问题 4

怎样判断 Sim2Real gap 来自哪里？

给出可执行的消融诊断。

先离线回放对比感知特征和动作分布，再固定视觉输入测试控制、固定控制目标测试感知；逐项替换真机相机、真实状态或仿真动力学参数，记录失败阶段。根据视觉、标定、延迟、动力学和接触分类建立消融，而不是笼统归因于 reality gap。

问题 5

BC 的局限能靠 Flow 解决吗？

区分动作多峰与闭环分布偏移。

Flow 能比单点 MSE 更好地表达多峰连续动作，但它仍可是在专家数据上做 BC，不能自动覆盖策略犯错后进入的状态。covariate shift 需要纠错/接管数据、DAgger、恢复技能或安全的在线后训练。

问题 6

模型如何处理触觉掉线？

不要回答“注意力会自动忽略”。

训练时做 modality dropout 与时间/噪声增强，并输入 validity/age mask；部署端监控心跳、时间戳、范围和饱和。低风险时可降级到视觉策略，高风险接触任务应保持、撤退或人工接管，不能让全零数据伪装成有效触觉。

问题 7

怎样证明策略用了触觉？

从相关性走向反事实证据。

做 no-tactile、时间打乱、左右交换、错误数量分布和只保留接触后触觉等干预，比较动作变化、严格成功率、数量误差和恢复率。只展示 Attention Map 或特征可视化不足以证明因果使用。

问题 8

部署延迟高先优化哪里？

先给延迟账本，再给压缩工具。

先记录 capture、传输、预处理、vision/VLM、生成采样、后处理、排队和机器人响应的 P50/P95。再针对最大项选择缓存、降低 token、减少采样步、量化或异步流水线，并用任务成功率、jerk 和 deadline miss 做回归。

问题 9

你是否做过完整 VLA 微调？

用边界清晰的经历回答。

我完成过多模态数据采集、LeRobot 转换、生成式动作策略训练和真机部署，也做过 G3 触觉推理输入链适配；尚未把这些表述为互联网规模 VLA 预训练或完整 AT-VLA 复现。我的下一步是基于现有数据做可控 LoRA/Action Expert 对比和固定真机评测。

问题 10

VLM Judge 能替代真机指标吗？

区分语义评估与物理可测量量。

不能。它适合辅助判断语言遵循和阶段完成，但精确数量、轨迹误差、碰撞、接触力、延迟和安全违规应由传感器与任务规则计算。使用 Judge 前还要验证其与人工标注的一致性。

问题 11

训练标签是关节角还是末端位姿？

先分清原始日志、策略输出和控制接口。

数据层尽量同时保留 q、末端 pose、夹爪状态和 commanded/executed action；策略可按迁移目标选择关节或末端增量。关节动作执行直接但绑定本体，末端动作更易跨本体却依赖坐标、IK 与底层控制。最后必须说明频率、绝对/增量、旋转表示和归一化。

问题 12

训练数据量应该怎样报告？

不要只报帧数或磁盘大小。

同时给 episode、有效小时、控制频率、有效 action windows，以及任务/物体/场景/操作者覆盖；说明过滤规则和 split 单位。逐帧随机切分会泄漏，同一 episode 生成的窗口必须留在同一 split。

问题 13

LoRA 效果和训练时长如何回答？

训练时间必须带模型、数据和硬件条件。

报告基座、插入层、rank、动作头更新范围、数据规模、分辨率、batch/steps、GPU/精度、显存和墙钟时间；效果同时比较离线指标与固定真机成功率。若尚无完整实验，就明确未完成并给对比计划，不编提升和时长。

问题 14

数据增强为什么可能让效果变差？

检查增强是否保持任务与动作标签。

增强可能遮掉关键接触区域、改变任务相关颜色，或在几何/时间变换后没有同步更新坐标、内参和 action target。应做单项消融，分别报告 ID、目标 OOD 和精细接触任务，不能只看平均训练 loss。

问题 15

数采 pipeline 遇到问题怎样排查？

用采前、采中、采后、训练四个 Gate 回答。

采前验证时钟、标定、单位与 schema；采中监控 tracking、心跳和队列；采后检查 timestamp、轨迹连续性、action/state、episode 与标签；训练前做回放、小样本过拟合和 split 防泄漏。再用 commanded/executed 轨迹区分数据问题与控制问题。

1. VLA 相比普通 VLM 最关键的新增信息是？

VLA 必须把语义理解落到机器人当前状态和控制空间。

2. 哪个模型使用 VLM + action expert + Flow Matching？

π₀ 使用预训练 VLM 骨干和连续动作专家。

3. LeRobot 格式能自动解决哪一项？

统一格式提供接口，但无法替代动作语义和标定检查。

4. Domain Randomization 的目标是？

随机化视觉、动力学和任务参数，使真实条件落入训练覆盖范围。
