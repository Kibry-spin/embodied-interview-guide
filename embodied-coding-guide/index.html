05 · DITFLOW · ELEVATOR PITCH

DiTFlow 不再是独立页面

以下从源码定位、张量、训练、采样、配置到面试追问全部放在 Main 中，并与 ACT、DiT、RTC、触觉和 VLA 联合理解。

30 秒回答

DiTFlow 是接入 LeRobot 的生成式机器人策略：它用 ResNet 编码最近多帧、多相机图像，并与本体状态拼成全局条件 c；训练时在高斯噪声 ε 与真实动作轨迹 a 之间采样直线插值点 xt，让条件 DiT 回归速度 a−ε；推理时从随机噪声出发，通过 Euler 法沿模型速度场从 t=0 积分到 t=1，得到完整 Action Chunk；策略再从当前时刻对应的索引开始截取若干动作放入队列，队列耗尽后结合新观测重新规划。

CONDITIONglobal c[B,S·Dcond]
→ modulate
FLOW STATExt, t[B,H,Da]
→ DiT
VELOCITYvθdx/dt
→ Euler
CONTROLaction dequeexecute e steps
训练输入xt, t, c

网络不是直接读取干净动作后复制动作。

监督目标a − ε

直线路径对 t 求导得到的常速度。

推理起点x₀ ~ N(0,I)

从与动作块同 shape 的随机噪声开始。

输出[B,H,Da]

整段连续动作，不是离散 action token。

代码边界

它是第三方 LeRobot policy 插件，不是完整训练框架。插件提供配置、策略、Flow loss、DiT 速度网络、采样与 processor；LeRobot 提供数据集、训练循环、统计量、policy factory、保存加载和机器人接口。复现时必须锁定兼容版本。

条件为什么不一定要 Cross-Attention？

该实现把定长 global condition 投影后与 t 相加，通过 AdaLN 生成每层 shift、scale、gate；这样计算便宜。若加入长语言序列或保留空间触觉 token，Cross-Attention 会更适合。

为什么动作时间步用 Self-Attention？

每个 token 对应轨迹中的一个时刻，Self-Attention 让所有时刻联合协调，适合双臂、灵巧手与接触阶段的跨时间依赖。

07 · DITFLOW · FLOW MATCHING

训练只做一次随机中间点回归

训练不是从噪声循环积分到动作；每个 batch 只随机采样一个 t，构造 xt 并回归该点的速度。

① PATHxt = (1−t)ε + ta

t=0 是噪声，t=1 是真实动作。

→
② TARGETut = a−ε

直线路径的 dx/dt 与 t 无关。

→
③ LOSS‖vθ(xt,t,c)−ut‖²

逐元素 MSE 回归条件速度场。

def flow_matching_loss(velocity_net, action, global_cond):
    B = action.shape[0]                         # action: [B, H, Da]
    noise = torch.randn_like(action)            # ε:      [B, H, Da]
    t = torch.rand(B, device=action.device)     # t:      [B]
    t3 = t[:, None, None]                       #         [B, 1, 1]

    x_t = (1 - t3) * noise + t3 * action        #         [B, H, Da]
    target = action - noise                     # dx/dt:  [B, H, Da]
    pred = velocity_net(x_t, t, global_cond)    #         [B, H, Da]
    return F.mse_loss(pred, target)
t[:, None, None]为什么需要 t3？

t 原本是 [B]，要分别乘每个样本的 H×Da 动作块；插入两个单例维后，PyTorch 才能按 batch 广播。

target = action - noise为什么不是预测 action？

网络参数化的是 ODE 速度场。路径从 ε 指向 a，因此切向量是 a−ε；推理再通过积分恢复动作。

velocity_net(x_t,t,c)三个输入分别做什么？

xt 告诉当前位置，t 告诉生成阶段，c 约束当前观测下应去向哪类动作。

INTERACTIVE PATHt = 0.50
NOISE0.50
ACTION0.50

xt = (1−t)ε + ta。拖动只改变训练输入的位置，直线路径的监督方向始终是 a−ε。

名称都可能叫 v定义监督与 sampler
Flow velocity概率路径的 dx/dt本页目标 a−ε；通过 ODE 积分
Diffusion v-pred常见定义 αε−σx₀是一种 DDPM 参数化，需要对应恢复公式
Noise ε-pred预测加到数据上的高斯噪声由 scheduler 计算反向更新
必须区分

Flow velocity 与 diffusion v 都可能在代码中叫 v，但数学定义、target 和采样方程不同。DiT 只是网络骨架，不决定它预测哪一种量。

08 · DITFLOW · SAMPLING & CONTROL

两个循环：ODE 生成，队列执行

内层多次调用速度网络生成 chunk；外层只在动作队列耗尽后重新读取观测。

INNER LOOP · GENERATION

噪声 → Action Chunk

@torch.no_grad()
def euler_sample(model, cond, shape, K=100):
    x = torch.randn(shape, device=cond.device)
    dt = 1.0 / K
    for k in range(K):
        t = torch.full((shape[0],), k / K,
                       device=cond.device)
        x = x + dt * model(x, t, cond)
        x = x.clamp(-1, 1)
    return x

从 t=0 正向积分到1。clamp 默认约束归一化动作，前提是 processor 的动作范围与之匹配。

OUTER LOOP · EXECUTION

Chunk → Action Queue

if len(action_queue) == 0:
    cond = encode(recent_observations)
    chunk = euler_sample(model, cond,
                         (B, horizon, action_dim))
    start = n_obs_steps - 1
    execute = chunk[:, start:start+n_action_steps]
    action_queue.extend(execute.transpose(0, 1))

action = action_queue.popleft()

连接 RTC

DiTFlow 队列属于同步“生成完再执行”。当 ODE 采样太慢或环境变化快时，RTC 让模型在执行当前 chunk 的同时生成下一段，并用旧动作前缀约束衔接。

10 · DITFLOW · RELATIONS

把 DiTFlow 放回整套知识体系

这部分是融会贯通的核心：同一段源码可以连接五个面试专题。

ACT ↔ DITFLOW同样输出 Action Chunk，不同生成目标

ACT 用 CVAE latent 和 L1+KL 一次回归；DiTFlow 用随机噪声和 velocity MSE，多步积分得到动作。

追问：在相同数据和执行 horizon 下，生成质量提升是否值得额外采样延迟？
TRANSFORMER ↔ DITSelf-Attention 处理动作时间 token

普通 Transformer Block 通过 t+c 的 AdaLN shift/scale/gate 变为条件向量场；不是因为用了 Transformer 就自动成为 diffusion。

追问：global condition 适合 AdaLN，长语言或触觉 token 何时应改 Cross-Attention？
TACTILE ↔ DITFLOW触觉是条件链路，不改变 Flow 公式

为触觉图像或向量设计 encoder，与视觉、本体按时间对齐后加入 c；重点是高频窗口、归一化、延迟和缺帧。

追问：触觉在 chunk 执行中途变化，何时触发重新规划？
RTC ↔ DITFLOW从同步队列升级为异步续写

DiTFlow 当前队列空后才重新生成；RTC 可边执行边生成，并在新 Flow 轨迹中约束已承诺前缀。

追问：Temporal Ensemble 输出后平均与 RTC 生成中约束有什么区别？
VLA ↔ DITFLOW小型策略是 Action Expert 的最小原型

11 · DITFLOW · INTERVIEW KIT

从公式连续追到真机

Q1：Flow Matching 与典型 DDPM 有什么区别？

两者都从噪声生成动作，但这里沿噪声到动作的直线路径回归 dx/dt，并通过 ODE 正向积分；典型 DDPM 常预测 ε、score 或 diffusion-v，按噪声日程做反向更新。Flow Matching 训练时同样使用噪声。

Q2：为什么还要输入 t，target 明明与 t 无关？

直线路径的条件 target a−ε 不显式依赖 t，但相同 x 值在不同 t 对应的信噪比和条件分布不同；网络需要 t 才能判断当前生成阶段并拟合正确条件场。

Q3：为什么用 DiT 而不是 1D U-Net？

动作时间步天然是 token，Self-Attention 便于建模长程协调并扩展模型规模；代价是注意力随 H² 增长。网络骨架选择不改变 Flow 目标。

Q4：horizon=16 为什么只执行8步？

生成 horizon 从最早观测对齐时刻开始。S=2 时索引0对应过去，当前动作从索引1开始；代码从 start=S−1 截取 e=8 步，其余不执行。

Q5：clamp(-1,1) 有什么前提？

动作必须由 processor 按数据统计量映射到匹配范围；否则每次 Euler 后裁剪会扭曲真实控制量。输出还要正确反归一化到机器人动作空间。

Q6：如何降低推理延迟？

先 profile 视觉编码与 K 次 DiT forward；优先评估减少积分步、减小模型、降低视觉分辨率、更好的 solver 或蒸馏。增大 e 只能摊薄调用，会降低反馈速度。

Q7：怎样加入触觉？

扩展 input feature、processor 与 condition encoder；触觉图像可保留空间 token，低维力信号可编码短时窗口。训练公式不变，但必须处理频率、延迟、归一化和缺失模态。

Q8：如何证明真的读过源码？

能说出配置注册、delta indices、condition 构造、t[:,None,None]、velocity target、Euler 方向、当前动作切片、processor 反归一化，以及公开实现的边界。
