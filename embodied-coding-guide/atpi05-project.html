01 · ELEVATOR PITCH

90 秒项目回答

推荐版本

我在银河自研双臂与 Sharpa 灵巧手平台上参与触觉 VLA 的部署与推理优化，工作对象是两个 ATPI05 checkpoint：一个输入十指 F6 力/力矩历史，另一个输入 Sparsh 编码的视触觉形变图像。ATPI05 不是官方 AT-VLA checkpoint 的完整复现，而是参考其触觉门控思想，在 StarVLA 的 OpenPI PI0.5 实现上做的方法级适配。落地时，现有代码缺少 checkpoint 中的 FastStateConditioner，我根据 6 个权重张量的 shape 反推 LayerNorm—MLP 结构，补齐快状态到 Action Expert adaRMS 的条件通路，并处理 bf16/fp32 混合 dtype，使两个模型都能 strict load。随后我依据训练 parquet 和 modality schema 纠正过时协议，确认 62 维状态/动作是左右 9D EEF 加左右 22D 灵巧手关节，并打通 WebSocket Server、客户端观测打包、归一化、动作反归一化和 GUI 切换。验证上，我不仅检查 shape 和 finite，还固定同一 Flow 初始噪声做触觉 on/off 消融，确认门控打开时触觉会改变动作、门控关闭时融合残差为零。性能上我先 profile，再只缓存去噪步间不变的 tactile tokens、mask 和 gate，保留每步随 xt 变化的注入计算，使 Deform 推理从约 253 ms 降至 157 ms，且输出 bit-identical；同时实现了模型侧 VLM 前缀 KV 跨周期复用并验证相同场景无损。当前已完成模型与开放环链路验证，但真实接触任务消融、在线 Deform、Server 级缓存调度和完整真机闭环仍在推进，所以我不会把它描述为论文完整复现或已完成多任务真机部署。

五句主线

为什么做：验证触觉推理链。最难点：代码、checkpoint、数据协议不一致。怎么解决：结构反推 + 契约对齐 + 分层测试。最有价值结果：因果验证与无损加速。边界：尚无真实任务级闭环结论。

06 · CHECKPOINT FORENSICS

缺少训练代码时，怎样恢复模型结构

01从 strict load 错误定位缺失模块

checkpoint 出现 6 个 fast_state_conditioner.* unexpected keys，说明权重存在但代码图中没有对应模块。

02按参数名和 shape 反推网络

input_norm 对应 LayerNorm(62)；network.0 对应 Linear(62,256)；network.2 对应 Linear(256,1024)，中间为无参数 SiLU。

03找到真正的条件注入位置

不是随便把 1024D 向量加到 hidden；需在 condition_action_suffix 后，与原 adarms_cond 合并，并同时覆盖训练 forward 和推理 denoise_step。

04处理混合 dtype

FastStateConditioner 以自身权重 dtype 计算；OpenPI 部分重新注册的 LayerNorm/adaRMS dense 保持 fp32，因此最终条件升到 fp32 再合并。

05用严格加载证明结构闭合

F6 共 842 keys、Deform 共 1013 keys；missing=0、unexpected=0、shape mismatch=0。

LayerNorm(62) → Linear(62,256) → SiLU → Linear(256,1024)

为什么这是有价值的工程工作

不仅让模型“能加载”，还要根据架构语义确定模块位于哪条条件路径、训练与推理是否一致、dtype 怎样穿过混合精度边界，并用完整 key 集验证。

为什么不能包装成算法创新

FastStateConditioner 已存在于 checkpoint 和配置语义中，你完成的是结构恢复、工程集成和正确性验证，而不是提出该模块。

两个阈值不能混为一谈

contact_force_threshold=1.0 是训练阶段从 raw F/T 生成 BCE 标签的物理阈值；0.6 是推理阶段对 sigmoid gate score 的无量纲阈值。模型探针中约 5 才跨过 0.6，是 learned gate 在该输入尺度下的行为，不应说成“系统把 5 N 定义为接触”。

11 · OPTIMIZATION 01

只缓存不随去噪步变化的触觉量

这是严格无损优化；关键不在“用了 cache”，而在于缓存边界选对了。

WRONG CACHE

缓存 conditioned suffix

base suffix 包含 xt 与 timestep，每个 Euler/Flow step 都变化。冻结整个注入结果会让动作偏差达到 1.3–1.7，约为初始噪声扰动敏感度的 5 倍。

  • 速度看起来变快
  • 数学语义已改变
  • 误差在积分中累积
CORRECT CACHE

缓存 tactile tokens / mask / gate

它们只依赖当前 observation，在同一次 action chunk 的 N 步去噪中不变；轻量 injector 每步仍读取新鲜 base suffix。

18 · INTERVIEW Q&A

项目追问与回答骨架

Q1：ATPI05 是你提出的吗？

不是。我参考 AT-VLA 的触觉门控思想，在团队的 StarVLA/OpenPI PI0.5 分支上做模型恢复、平台适配、部署链路与推理优化。我的贡献在工程实现、正确性验证和计算图优化。

Q2：为什么叫 method-level port？

官方 AT-VLA 不基于 Physical Intelligence PI0.5，且没有公开完整训练/机器人评测。ATPI05 复用方法思想，但基础模型、动作维度和 checkpoint 都不同，不声称 checkpoint-compatible 复现。

Q3：为什么能从 6 个权重恢复模块？

参数名给出层级，shape 给出输入/输出维：LayerNorm 62、Linear 62→256、Linear 256→1024；两层 Linear 之间需要无参非线性。更关键的是从调用图确认它应合并到 adaRMS，而非直接加到 hidden。

Q4：Strict load 通过证明了什么？

证明代码结构与 checkpoint 参数 schema 一致；不证明 forward 语义、数据契约或任务效果，因此还需要 dtype、协议、消融和回放测试。

Q5：为什么 62D 不看旧协议？

协议可能过时，训练数据才是模型监督的真实来源。我对照 modality.json 与 parquet，检查 Rot6D 数值约束，并确认 normalizer 只按 flat 维度工作，最终确定 9+9+22+22。

Q6：绝对动作与 delta 动作弄错会怎样？

若把 absolute target 再累加到当前 pose，会产生巨大漂移；反过来把 delta 当 absolute 会跳向零附近。必须由训练字段、统计范围和执行器接口共同确认。

Q7：触觉门控为何需要 BCE？

仅靠动作 loss，Gate 可能学成始终开/关的捷径。BCE 提供明确接触监督；总损失用较小 0.01 权重，避免门控分类压过 Flow action learning。

Q8：为什么用 hard gate + straight-through？

推理希望非接触时残差严格为零，避免噪声污染；训练仍需要 sigmoid 的软梯度，因此前向二值、反向沿 soft probability 传播。

Q9：30% 动作变化是不是说明触觉更好？

不是，只说明门打开后触觉分支对输出有因果影响。方向是否正确、任务是否改善，需要真实数据 mismatch 和真机触觉 on/off 成功率。

Q10：Deform 为什么一个 seed 没触发 Gate？

合成“强形变”不一定落在训练分布；这恰好说明合成探针只能验证通路，不能替代真实接触标定，也不能说 Gate 对所有形变都鲁棒。

Q11：缓存 tactile tokens 为什么无损？

在同一次 Flow 采样中 observation 不变，encoder output、mask 和 gate 只依赖 observation；每步变化的是 xt、t 与由此得到的 suffix query，所以这些必须重算。

Q12：prefix KV 为什么不是总能复用？

相同图像/语言时严格等价；真实相机连续变化时旧 KV 丢失新视觉信息。状态更新仍在，但物体移动、遮挡或任务切换会使缓存失效，因此必须有刷新策略。

Q13：为什么不直接减少 denoise steps？

减少 steps 很有效但可能降低动作质量，属于有损杠杆；先删除严格冗余可获得无损收益，再用任务成功率选择最小可用 steps。

Q14：为什么不优化网络？

Server 与直连差异小于约 15 ms，模型前向是主要瓶颈。先用 profiling 证明瓶颈，再投入计算图和采样优化。

Q15：3:1 现在完成了吗？

模型侧 prefix cache 和快状态通路已完成并验证，Server 的跨请求 cache、刷新和异步 worker 尚未接入。因此目前是快慢架构的模型级原型，不是完整线上 3:1 系统。

Q16：项目最大的工程收获？

机器人模型部署的正确性不来自一次 forward，而来自模型 schema、数据语义、归一化、随机采样、服务协议和执行接口逐层闭合；优化也必须先区分静态观测依赖与动态 solver state。
