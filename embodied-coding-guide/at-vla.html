01 · ELEVATOR PITCH

先背这一分钟

60 秒回答

AT-VLA 面向拉拉链、擦拭、旋盖等接触丰富任务，解决两个问题：第一，预训练 VLA 很少见过触觉，直接追加触觉 token 可能扰乱原有视觉定位；第二，大型 VLM 推理较慢，无法及时利用高频接触反馈。它在 GO-1 的 VLM 加动作专家架构上加入轻量触觉编码器和 Tactile Gate：无接触时保持原有 state query，接触时切换为 tactile query；同时缓存低频视觉语言特征，让触觉快速流在同一 action chunk 时域内多次更新动作。论文用动作损失与接触门控损失联合训练，并在推理时采用 3:1 的快慢流频率比。我的 ATPI05 工作不是官方 checkpoint 复现，而是参考该方法，在 StarVLA/OpenPI π0.5 上完成的触觉适配工程：已完成 checkpoint 结构恢复、62D 双臂灵巧手协议、开放环协议验证、受控门控因果测试与模型级缓存优化；真实触觉标定和任务级真机闭环仍在推进。

记忆主线

为什么加：接触反馈；为什么不能直接加：干扰预训练；何时加：Gate 判断接触；加在哪里：Action Expert 的 Query；如何加快：慢 VLM 缓存 + 快触觉更新。

03 · MOTIVATION

AT-VLA 解决的两个冲突

CONFLICT 01

新触觉 vs. 预训练知识

VLA 预训练数据主要是视觉、语言和机器人状态。下游阶段突然追加从未见过的触觉 token，可能改变 Action Expert 的注意力分布，让模型从目标物体转移到无关区域，连接触前抓取定位也退化。

  • 不是“触觉越多越好”
  • 需要控制注入时机与位置
  • 非接触阶段应尽量保持原模型行为
CONFLICT 02

大 VLM vs. 高频反馈

接触后的滑移、卡滞和碰撞风险要求快速修正，而完整 VLM 每一步都重新处理多路图像和语言，推理频率往往低于触觉和控制环所需频率。

  • 语义与定位可以低频更新
  • 接触反馈必须高频刷新
  • 使用缓存条件连接两种频率

WHY DIRECT CONCAT FAILS

直接拼接为什么可能更差

01分布外输入

触觉是预训练阶段缺失的新模态，其统计分布与视觉/文本 token 不同。

02序列结构改变

额外 token 改变注意力竞争关系、位置结构和条件权重。

03接触前也被干扰

如果全程注入，即便传感器没有有效接触，模型仍必须解释噪声或零值。

04视觉定位退化

论文注意力可视化与消融显示，直接注入的平均成功率低于原始 GO-1。

WHEN

接近、定位和抓取前阶段尽量复用原始 VLA；传感器确认接触后才扩大触觉影响。

WHY

代码中的 Adaptive Cross-Attention 怎么理解

论文用简洁形式描述：VLM 的图像/语言 token 提供 K/V；无接触时 state token 做 Q，接触时 tactile token 做 Q。公开代码的实现更工程化：先把 tactile token、分隔 embedding 与 state/action 轨迹拼成 Action Expert 序列；gate 激活时使用完整分支 hidden states，未激活时用末 33 个 state/action token 重复构造 query，并主要保留末 33 个 token 的层更新。面试时先讲论文抽象，再补充“代码通过 mask 和序列重构近似实现 Query 切换”，不要只背类名。

0.04 s 的正确解释

这是论文报告的闭环反应/推理速度，不应直接表述成“完整 G3 控制系统 25 Hz”。真实闭环还包含传感器采样、网络传输、预处理、动作后处理、机器人通信和执行器延迟，需要端到端时间戳测量。

公开 deploy 还不是完整 3:1 调度器

代码提供 cached_vlm_features 入口，并能将 slow/fast 三路图像分开处理，但当前 debug 主循环仍是一条样本调用一次完整 forward；没有发布常驻的“慢流每 3 次更新一次、快流连续执行”的真机线程/调度逻辑。G3 部署需要自行实现缓存生命周期、并发和安全控制。

08 · TRAINING & ACTION GENERATION

联合目标与扩散动作头

L = Laction + 0.01 · Lgate
ACTION OBJECTIVE

Laction

GO-1/DiT 动作专家的扩散式动作监督。代码给动作加 DDPM 噪声，并以 MSE 预测干净 action sample。

GATE OBJECTIVE

Lgate

论文使用接触/非接触标签的 BCE，使触觉编码器和门控网络显式理解接触阶段。

14 · INTERVIEW DRILLS

高频追问与回答骨架

QUESTION 01

AT-VLA 为什么不直接把触觉 token 拼到 VLM 输入？

从预训练分布、注意力竞争和接触阶段回答。

预训练 VLA 很少见过触觉，直接追加 token 会改变原有序列与注意力竞争，可能使 Action Expert 的注意力从目标物体偏移，连接触前视觉定位都退化。触觉在非接触阶段通常没有有效信息，因此 AT-VLA 保持 VLM 的图像/语言条件结构，只在 Gate 判断接触后让 tactile token 主导 Action Expert Query。

QUESTION 02

Tactile Gate 和普通力阈值有什么区别？

既要说学习能力，也要说工程风险。

普通阈值直接在原始力上判断，简单、可解释但难适应不同物体、方向和传感器漂移；Tactile Gate 在编码后的触觉 token 上学习接触分类，可利用多维组合关系并与动作目标联合训练。代价是需要接触标签、训练分布和阈值标定，还要防止抖动，工程上可加入迟滞、最小保持时间或安全硬阈值。

QUESTION 03

快慢双流如何保证条件不过期？

不要只回答“缓存 KV”。

slow stream 的视觉语言输出只在 action chunk horizon 内复用；每份 cache 应记录 observation timestamp、版本号和有效期。fast stream 每次读取最新触觉与状态，同时检查 cache 是否仍对应当前任务和场景；如果相机变化、任务切换、缓存超时或 Gate 关闭，应触发慢流更新或回退。真实系统还要防止并发读写时拿到不完整 KV。

QUESTION 04

为什么 6D force 比触觉图像表现更好？

限定在论文设置中。

在 AT-VLA 的数据规模和注入方式下，6D force 是紧凑、任务相关的接触表征，token 少、编码快，也较少扰动预训练表示；触觉图像需要额外 ViT 并产生更多 token。论文结果只说明这套设置下 force 6D 最好，不意味着高维触觉普遍更差，高维信号可以先经过任务相关瓶颈再融合。

QUESTION 05

AT-VLA 没有触觉时为什么还能运行？

回答机制，不要说“模型脑补触觉”就结束。

Gate 关闭时 Query 和输入行为尽量退化到原始 VLA，因此不会强依赖触觉 token；训练中模型仍保留预训练视觉语言能力，并可能从视觉与状态中学到与接触相关的相关性。论文显示无触觉时非接触任务保持基线水平，但接触丰富任务仍明显受益于真实触觉，不能把鲁棒性理解为触觉可有可无。

QUESTION 06

你目前到底完成了什么？

用证据和边界回答。

我完成的是 ATPI05 的模型/协议级工程验证，而不是官方 AT-VLA 的任务复现：补齐 checkpoint 中缺失的 62→256→1024 状态条件器，F6 842 个键和 Deform 1013 个键均严格加载；按真实数据元信息纠正 62D 双臂末端与手指布局，打通客户端—服务端—动作解析；用固定初始噪声验证门控关闭时动作差异为零、开启后触觉会改变动作；并完成逐元素一致的触觉缓存优化。真实 MCAP 门控标定、在线 Deform、运行时 3:1 调度和安全真机闭环仍未完成。
