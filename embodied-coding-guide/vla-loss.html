02 · BASIC LOSSES

交叉熵与 MSE 从头写

先判断输出是什么：离散 token 用交叉熵，连续向量直接回归常用 MSE。

CE = −log softmax(logits)target
cross_entropy_from_scratch.py
import torch

def stable_cross_entropy(logits, target, reduction="mean"):
    """
    logits: [N,C]，target: [N]，每项是类别索引
    """
    # logsumexp 内部使用减最大值技巧，避免 exp 溢出
    log_probs = logits - torch.logsumexp(logits, dim=-1, keepdim=True)
    target_log_prob = log_probs.gather(1, target[:, None]).squeeze(1)
    loss = -target_log_prob

    if reduction == "none":
        return loss
    if reduction == "sum":
        return loss.sum()
    return loss.mean()

# 如果面试官明确要求“softmax + log”版本：
def ce_with_clamp(logits, target, eps=1e-8):
    probs = torch.softmax(logits, dim=-1)
    probs = probs.clamp(min=eps)  # 防止 log(0)
    p_target = probs.gather(1, target[:, None]).squeeze(1)
    return (-torch.log(p_target)).mean()
优先写 logsumexp / log_softmax 版本

clamp 能防止 log(0)，但直接在概率域计算仍可能先发生 softmax 的上溢或下溢。PyTorch 实际使用时直接调用 F.cross_entropy。

MSE = (1/N) Σ(ŷi−yi)²
mse_from_scratch.py
def mse_loss(pred, target, mask=None):
    # pred / target: [B,H,D]
    error = (pred - target).pow(2)

    if mask is None:
        return error.mean()

    # mask: [B,H]，True 表示有效动作；扩一维后广播到 D
    weight = mask.unsqueeze(-1).to(error.dtype)
    valid_elements = weight.sum() * error.size(-1)
    return (error * weight).sum() / valid_elements.clamp(min=1)
SHAPE逐元素平方

先保留完整 [B,H,D] 误差，最后再聚合，便于加权或 mask。

MASK不要平均 padding

变长轨迹补齐后，分母必须只统计有效元素。

GRADIENT梯度正比于误差

异常值会产生更大梯度；必要时可考虑 Huber loss。

动作表示网络输出常用 Loss关键点
离散 action token[B,L,V]Cross Entropy类别维是词表 V；目标为整数索引

04 · TRAIN & SAMPLE

Flow Matching 最小训练与 Euler 采样

动作 a、噪声 ε、中间状态 x_t 和预测速度形状都为 [B,H,D]。

flow_matching_loss.py
def flow_matching_loss(velocity_net, action, cond):
    # action: [B,H,D]，cond: [B,C]
    B = action.size(0)
    noise = torch.randn_like(action)                  # [B,H,D]
    t = torch.rand(B, device=action.device)           # [B]
    t3 = t[:, None, None]                             # [B,1,1]

    x_t = (1.0 - t3) * noise + t3 * action            # [B,H,D]
    target_velocity = action - noise                  # [B,H,D]
    pred_velocity = velocity_net(x_t, t, cond)        # [B,H,D]

    return (pred_velocity - target_velocity).pow(2).mean()
euler_sample.py
@torch.no_grad()
def sample_action(velocity_net, cond, shape, num_steps=100):
    x = torch.randn(shape, device=cond.device)         # t=0: [B,H,D]
    dt = 1.0 / num_steps

    for i in range(num_steps):
        t = torch.full(
            (shape[0],), i / num_steps,
            device=x.device, dtype=x.dtype,
        )                                             # [B]
        velocity = velocity_net(x, t, cond)            # [B,H,D]
        x = x + dt * velocity                          # 显式 Euler

    return x                                           # t≈1 的动作块
TRAIN随机覆盖所有时间

每条 batch 样本独立采样 t，让网络学习整条运输路径上的速度。

INFERENCE从噪声积分

每一步用当前状态、当前 t 和条件重新预测局部速度。

CONDITION决定生成什么动作

视觉、语言、本体和触觉通常先编码为条件 c，再注入速度网络。

t3=t[:,None,None] 是为了广播，不是第三个时间

原始 t 为 [B]，网络时间编码器使用它；与三维动作轨迹运算时扩成 [B,1,1]，在 H 和 D 上自动广播。

05 · ACTION CHUNK

一次预测一段动作

相比单步动作，chunk 联合建模短期时序并降低模型调用频率；代价是块内反馈滞后，需要在执行长度与闭环频率间折中。

观测窗口[B,S,...]
→
策略生成[B,H,D]
→
截取执行[B,K,D]
→
逐步出队[B,D]
→
队列耗尽重新规划
sliding_action_chunks.py
def sliding_chunks(actions, horizon, stride=1):
    """actions: [T,D] -> chunks: [N,H,D]"""
    T = actions.size(0)
    starts = range(0, T - horizon + 1, stride)
    chunks = [actions[s:s + horizon] for s in starts]
    return torch.stack(chunks, dim=0)

# T=100, H=16, stride=1 -> N=85
# 第0块: action[0:16]；第1块: action[1:17]
chunks_with_valid_mask.py
import torch.nn.functional as F

def chunks_with_padding(actions, horizon, stride=1):
    T, D = actions.shape
    chunks, masks = [], []

    for start in range(0, T, stride):
        chunk = actions[start:min(start + horizon, T)]
        valid = chunk.size(0)
        chunk = F.pad(chunk, (0, 0, 0, horizon - valid))
        mask = torch.arange(horizon, device=actions.device) < valid
        chunks.append(chunk)
        masks.append(mask)

    return torch.stack(chunks), torch.stack(masks)
    # [N,H,D], [N,H]
action_queue.py
from collections import deque

class ChunkExecutor:
    def __init__(self, policy, execute_steps):
        self.policy = policy
        self.execute_steps = execute_steps
        self.queue = deque()

    @torch.no_grad()
    def select_action(self, observation):
        if not self.queue:
            chunk = self.policy(observation)          # [1,H,D]
            selected = chunk[0, :self.execute_steps]  # [K,D]
            self.queue.extend(selected.unbind(0))

        return self.queue.popleft()                   # [D]
为什么 H 和 K 可以不同？

H 是模型联合建模的预测 horizon，K 是每次真正开环执行的步数。保留较长 H 可以学习动作结构，使用较短 K 可以更快结合新观测重新规划。

06 · TEMPORAL ENSEMBLE

融合重叠 chunk 对同一时刻的预测

每个控制时刻都可重新预测完整 chunk，因此当前动作会拥有来自不同历史时刻的多个候选值。

ât = Σiwiât(i) / Σiwi,   wi=exp(−ki)
交互融合示例（候选按“最新 → 最旧”排列）
temporal_ensemble.py
def temporal_ensemble(candidates, decay=0.01):
    """
    candidates: [N,D]，明确约定第 0 行最新，第 N-1 行最旧
    """
    N = candidates.size(0)
    age = torch.arange(N, device=candidates.device, dtype=candidates.dtype)
    weights = torch.exp(-decay * age)                 # [N]
    weights = weights / weights.sum()
    return (candidates * weights[:, None]).sum(dim=0) # [D]

# 维护预测表时：第 s 次推理得到 chunk[s:s+H]
# 执行时收集所有覆盖当前全局时刻 t 的预测，再按新旧融合。
权重方向必须结合数组顺序说明

不要只背 exp(-ki)。如果候选数组按“最旧→最新”存储，就需要反转 age 或候选顺序，才能保证你想强调的预测获得更大权重。

def fm_loss(net, a, c):
    B = a.size(0)
    eps = torch.randn_like(a)
    t = torch.rand(B, device=a.device)
    t3 = t[:, None, None]
    xt = (1-t3)*eps + t3*a
    return (net(xt,t,c) - (a-eps)).pow(2).mean()

08 · QUICK CHECK

五题快速自测

1. 手写交叉熵时，数值最稳定的实现是？

logsumexp 使用减最大值技巧，避免概率域的上溢和下溢。

2. Flow Matching 直线路径的目标速度是？

对 xₜ=(1−t)ε+ta 求导得到 a−ε。

3. t:[B] 扩成 t[:,None,None] 的目的？

t3 shape 是 [B,1,1]，同一样本的整条轨迹共享一个 t。

4. Action Chunk 中减小执行步数 K，通常意味着？

K 控制开环执行长度；更小的 K 能更快利用新观测重新规划。

5. Temporal Ensemble 最容易出现的实现错误是？

公式里的索引 i 必须与候选的时间新旧顺序一致。
