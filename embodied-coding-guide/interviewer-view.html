01 · EVALUATION RUBRIC

我会怎样判断候选人

重点不是术语覆盖率，而是回答能否从抽象机制落到张量、时间、坐标和真机证据。

动作表示与生成25%先定义 action 语义，再比较 MSE、AR、Diffusion、Flow 的目标与推理代价只说“Flow 更先进”，说不出 shape、horizon、控制频率和反归一化

LEVEL 1

会复述

知道论文模块和常用名词，但一追问 action 语义、数据时间轴或控制接口就回到概念描述。

LEVEL 2

会实现

LEVEL 3

会闭环

能定义跨模块契约、量化误差与延迟、设计最小证伪实验，并根据失败更新数据、模型或控制系统。

GENERATION FAMILIES

四类动作生成方法怎样取舍

方法训练目标优势局限适合场景
直接回归 / MSE最小化 ‖â−a‖²，近似条件均值训练和推理快、实现简单、延迟低多种合理动作并存时容易平均，产生“谁都不像”的轨迹单峰、确定性强、低延迟任务；也可作为强基线

Diffusion回归噪声、score 或 diffusion velocity适合连续、高维、多峰 action chunk，训练稳定多步去噪增加推理延迟；solver/schedule 影响结果复杂操作、多解轨迹和离线模仿学习

Action token 的正确理解

连续动作先归一化和离散化，再映射为词表 token。token ID 是类别索引，不应直接当连续动作距离。在 OpenVLA 一类标量分桶中，bin 与保留 token 可以按顺序映射，相邻 bin 对应相近标量；但 CE 对“错一个 bin”和“错很多 bin”没有天然距离感知。FAST 经 DCT、量化和 BPE 后，一个 token 还可能代表压缩的频域子序列，此时 ID 数值更无物理邻近意义。

为什么 MSE 会平均多峰？

对固定 observation，如果专家可能从物体左侧或右侧绕行，平方误差的最优单点预测接近两种模式的均值，可能落在障碍物中。问题不是 MSE 数值不稳定，而是单点条件均值不能表达多峰分布；可改用 mixture、CVAE、Diffusion 或 Flow。

04 · ARCHITECTURE READING

π₀、π₀.₅ 与 GR00T 应怎样讲

不要只背“VLM + Action Head”；要说清专家、token、attention 和训练目标如何连接。

架构VLM 与动作模块的连接动作生成面试重点
π₀单个 Transformer 中有两套 expert 权重：图像/语言走 VLM expert，state/noisy action 走 action expert；两类 token 通过 self-attention 交互Action Expert 对整段连续动作做 Flow Matching；动作 token 可看观测 prefix 和彼此不是“取最后 hidden state 接 MLP”；blockwise mask、专家路由和 KV cache 都是架构的一部分
π₀.₅预训练阶段还预测 FAST action token；后训练加入 Flow Action Expert。VLM prefix 到 action expert 是单向信息流，expert 不看 FAST action token高层可自回归输出语义子任务；低层 Flow Expert 输出连续 50-step chunk异构 co-training、高低层统一模型、FAST→Flow 两阶段，以及 mask 的真实作用边界
GR00T N1VLM System 2 编码图像和语言，其输出与机器人 state/action encoding 一起送入 DiT System 1DiT 使用 Flow Matching 产生高频连续 action chunk功能上语义/动作模块清晰分工，但论文明确两者紧密耦合并端到端联合训练，不能说成完全独立系统
π₀ 为什么不是 last hidden + head？

π₀ 为每个 noisy action timestep 构造动作 token，state 和动作进入较小 action expert，图像/语言 token 进入预训练 VLM expert；它们在同一个 Transformer 的 self-attention 中交换信息。动作块内部是双向 attention，动作 token 直接查询整个输入 prefix。

“Knowledge insulation”怎样严谨回答？

π₀.₅ 的 attention mask 使 VLM embedding 不 attend action expert，信息从 VLM prefix 单向流向 Flow expert，并禁止 Flow action token 看 FAST action token以避免两种动作表示泄漏。可以把它理解为表征层面的隔离；但mask 不等于 stop-gradient，action expert 读取 VLM K/V 时，action loss 仍可能沿计算图影响上游。论文还通过 next-token 与 Web/高层数据联合训练维持语义能力。

GR00T 的“解耦”是什么？

System 2 负责视觉语言语义表示，System 1 的 DiT 负责高频连续控制，因此模块职责和动作参数化是解耦的；但它不是两个完全分离、只靠文本通信的服务，官方论文称其 tightly coupled、jointly trained end-to-end。

比较架构不能漏什么？

除了 backbone 名称，还应比较 action space、chunk 长度/频率、condition 粒度、训练目标、attention mask、梯度范围、采样步数、缓存方式、跨本体适配和在线延迟。

不要把论文概念口号化

“知识隔离”“语义动作解耦”“快慢系统”都要落到可执行问题：是哪组 token 不可见？哪个 loss 更新哪些参数？两个模块交换什么张量？交换频率、时间戳和失败返回是什么？

05 · VLA VS WAM

一个回答“做什么”，一个评估“做了会怎样”

这是功能定位，不是绝对二分；World-Action Model 也可能联合生成未来表示和动作。

VLA: p(A | o, ℓ)　　World Model: p(o′ or z′ | o, A)　　Planning: argmaxA Score(ŏ′)
维度直接 VLAWAM / Action-conditioned World Model
主要输出动作或 action chunk未来像素、latent、状态；部分模型也联合预测动作
决策方式观测到动作的摊销映射，一次/少步生成预测候选动作后果，再规划、排序或反事实比较
优势链路短、推理直接、容易达到实时控制显式建模动力学，可做候选评估、安全检查和更丰富预训练
风险缺少显式后果模型，失败原因较难解释预测误差复合；视觉上合理不等于物理可执行；视频生成成本高
关键评测任务成功、轨迹质量、反应延迟除任务成功外还要验证 action sensitivity、时序一致性和反事实排序能力
WAM 怎么用于安全检查？

前提是模型对 action 条件敏感。对多个候选 action rollout 未来状态，检查碰撞、工作空间、接触或任务风险，再选择/否决候选；高风险约束仍应由几何碰撞检测和底层安全控制器兜底，不能只信生成视频。

怎样识别世界模型没学 action？

固定 observation，系统性改变 action，检查未来预测是否按物理方向变化；用 action shuffle、zero-action、反向 action 和真实下一状态对照。若各种 action 产生相似未来，模型可能主要依赖视觉先验。

08 · SYMPTOM → ROOT CAUSE

从症状设计最小证伪实验

症状优先检查最小实验不要先做
每次都稳定抓偏同一方向相机内外参、base↔camera、TCP、深度尺度、图像 crop/resize 映射固定标定点和 AprilTag；将 3D 目标投影回图像；低速走到多个已知点测系统偏差直接重新训练或增加随机增强
raw action 平滑，机器人抖反归一化、绝对/增量语义、IK 支路、控制增益、发送周期、网络 jitter并排画 raw→command→measured；先空载低速回放同一 command把模型 loss 换成更强平滑项
raw action 本身抖观测抖动、时间错位、chunk 边界、采样噪声、condition 是否变化冻结 observation 重复推理；比较同 seed/不同 seed；画相邻 chunk 重叠区只调 PID
离线 loss 好、真机差数据泄漏、预处理/stats 不一致、action target 与 executed 不一致、covariate shift保存真机 observation 离线重放；逐 tensor 比较训练和部署 pipeline只报告 validation loss
反应总是慢半拍相机曝光/缓冲、推理时延、action queue、训练 target 是否做 latency matching用突发事件测 capture→command→motion 时间线；改变执行 horizon盲目提高控制频率
仅接触阶段失败触觉/力信号同步、接触状态分布、刚度/摩擦、动作频率和安全裁剪分阶段统计；回放同一预接触轨迹，改变末端速度/力阈值把所有失败归因于视觉
换场景或光照立即失效视觉分布、曝光/白平衡、crop、语言目标绑定、背景捷径固定几何只变光照/背景；feature 可视化和对照增强把它叫作“Sim2Real”后停止分析
轨迹抖动怎么判断来自模型还是控制？

画三条同一时间轴曲线：模型原始输出 araw、控制器接收命令 acmd、机器人实测 ameas。若 raw 已抖，查观测/模型/chunk；raw 平滑而 cmd 抖，查后处理/IK；cmd 平滑而 measured 抖，查通信、控制器和机构。

稳定偏差为什么先查标定？

稳定、可重复、方向一致的误差更像确定性系统偏置，而非策略随机性。可用多点位姿误差拟合：常量平移提示 TCP/外参，随距离放大提示尺度，随姿态旋转提示 frame 或旋转外参。

09 · NEW EMBODIMENT

新机器人迁移先设计中间动作接口

“不要直接输出 30+ DoF”不是绝对定律，而是跨本体、数据有限和安全要求较高时更稳健的工程默认。

系统思维

一条失败可以同时跨层，但 Root Cause Analysis 仍要找“最早出现异常的层”。例如目标 pose 已经偏了，就先解决感知/标定；目标正确但 IK command 跳变，才进入控制接口；command 平滑而实测抖动，再查控制器与硬件。

我会重点问的十四个问题

主问题确认基础，追问确认是否真正理解，证据问题确认是否亲自做过。

主问题递进追问强回答信号

6. π₀ 为什么不是最后 hidden 接 head？两套 expert 权重如何通过 self-attention 交互？提到 token routing、block mask、noisy action token

判断是否“亲自做过”

继续问一个具体失败、当时看到的日志/曲线、最小验证实验、最终修改和指标变化。真实工程经历通常包含不完美的中间过程，而不只是顺滑的最终架构。

12 · ONSITE CASES

四道现场系统题

不要求唯一答案，重点观察假设、测量、优先级和安全意识。

Case A · 抓取点始终向右偏 3 cm

期望路径：先确认偏差是否随深度/姿态变化；检查 RGB-D 对齐、depth unit、camera→base 外参、TCP；用多个已知 3D 点验证变换与重投影。几何链正确后，再固定 observation 查看模型 raw target 是否已偏。
加分：能从误差模式判断常量偏置、尺度或旋转误差。

Case B · 每个 action chunk 交界处抖一下

期望路径：画相邻 chunk 的重叠区、队列索引和实际发送时间；检查是否从错误 offset 开始执行、旧新 chunk 是否直接覆盖；对比 temporal ensemble、prefix/inpainting RTC 或缩短执行 horizon。
加分：同时评估平滑和响应速度，而非只加低通。

Case C · 新机器人关节数翻倍

期望路径：先选跨本体 action interface，而非直接 zero-pad；优先评估任务空间末端/手部 synergy + IK/WBC，建立 action/state adapter；离线检查可达率、碰撞与速度，再采集本体特定数据微调。
加分：能说明何时全关节端到端更合适。

Case D · WAM 预测视频很好但控制没提升

期望路径：检查未来预测是否 action-sensitive，而非仅复现视觉先验；比较候选动作的排序与真实 rollout；区分像素质量和任务相关 latent；检查规划延迟与模型误差是否抵消收益。
加分：提出 action shuffle/zero-action/反向 action 干预。

一票否决式危险信号

无法说明 action 单位/坐标；真机未做安全限幅和超时；把内部未完成工作包装成完整复现；把他人系统贡献当个人成果；遇到问题同时修改多层且没有对照；只展示成功视频而没有失败分类和固定评测。
