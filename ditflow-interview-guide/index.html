01 · ELEVATOR PITCH

先把一句话讲对

面试时先给结论，再按“输入—训练目标—推理—执行”展开。

30 秒回答
DiTFlow 是一个接入 LeRobot 的生成式机器人策略：它先用 ResNet 编码多相机图像，并与本体状态拼接为全局条件；训练时在高斯噪声与真实动作轨迹之间做线性插值，让 DiT 回归从噪声指向动作的速度场；推理时从随机噪声出发，用 Euler 法积分该速度场得到一段动作轨迹，再通过动作队列分步执行。
输入历史观测

本体状态 + 一路或多路图像，也可加入环境状态。

监督速度场

目标不是 ε，而是动作与噪声之差 a − ε。

生成ODE 积分

从 t=0 的噪声沿速度场走到 t=1 的动作。

执行动作分块

一次生成 horizon，截取当前起的 n_action_steps 入队。

展开 2 分钟回答框架适合追问“具体怎么实现？”
  1. 定位：这是第三方 LeRobot policy 插件，复用了 LeRobot 的配置、数据特征、RGB 编码器、训练入口和预后处理体系。
  2. 条件：对最近 n_obs_steps 帧图像做 ResNet + SpatialSoftmax 编码，与对应的机器人状态、可选环境状态拼接并展平，得到全局条件 c。
  3. 训练：采样真实动作 a、高斯噪声 ε 和时间 t，构造 x_t=(1−t)ε+ta，DiT 预测速度，使用 MSE(vθ, a−ε)。
  4. 推理：从与动作块同形状的高斯噪声出发，反复执行 x ← x + Δt·vθ(x,t,c)，默认 100 步，得到完整动作轨迹。
  5. 部署：默认观察 2 帧、生成 16 步，只取从当前时刻开始的 8 步，逐步从队列弹出；队列耗尽后再结合最新观测重新规划。

03 · FLOW MATCHING

训练：学的是“该往哪走”

这三行公式是全仓库最值得背下来的内容。

① 采样路径上的点

xt = (1 − t) ε + t a

t=0 是噪声，t=1 是真实动作轨迹
→
② 路径速度是常数

ut = d xt/dt = a − ε

直线路径的切向量
→
③ 回归条件速度场

L = ‖vθ(xt,t,c) − (a−ε)‖²

代码中直接使用逐元素 MSE
modeling_ditflow.py · compute_loss
# ε 与真实动作 a 具有相同形状
noise = self.velocity_net.sample_noise(B, device)
t = self.noise_distribution.sample((B,))

# x_t = (1-t)ε + ta
x_t = (1 - t[:, None, None]) * noise \
    + t[:, None, None] * trajectory

pred = self.velocity_net(x_t, t, global_cond)
target = trajectory - noise
loss = F.mse_loss(pred, target)
为什么 target 是 a−ε？

因为插值路径对时间求导后正好是 a−ε。网络学习任意中间点在条件 c 下应沿哪个方向移动。

为什么能表示多模态动作？

同一观测可从不同初始噪声出发，速度场把不同样本运输到动作分布的不同模式。

t 怎么采样？

默认均匀采样；也提供来自 π0 设置的变换 Beta 分布，使不同噪声区间获得不同训练权重。

04 · ROLLOUT

推理：生成一段，执行一段

理解两个循环：内层是 ODE 生成，外层是动作队列执行。

A

ODE 生成循环

初始化与整段动作同形状的噪声，默认迭代 100 次：

dt = 1 / K
for k in range(K):
    t = k / K
    x = x + dt * v_theta(x, t, condition)
    x = clamp(x, -1, 1)  # 默认开启
输出[B, horizon, action_dim]
B

动作队列循环

默认 S=2、horizon=16、n_action_steps=8：

过去当前未来
t−1tt+1···t+7···t+14
使用 2 帧观测
执行 8 步
切片actions[:, S−1 : S−1+n_action_steps]
＋动作连贯

一次联合生成整段轨迹，能够建模时间依赖，减少逐步预测的抖动。

＋降低推理频率

ODE 采样开销较高，生成后连续执行 8 步，摊薄模型调用成本。

−反馈滞后

动作队列未耗尽时不会重新生成；执行块越长，对突发变化的反应越慢。

05 · FOUNDATIONS

三个必须讲清的相关知识点

多模态决定“条件从哪里来”，生成式模型决定“动作如何表示”，Action Chunk 决定“轨迹怎样落到控制循环”。

MULTIMODAL CONDITIONING

不同模态先各自编码，再在同一时间轴上融合

本仓库实际使用图像、本体状态和可选环境状态。图像经共享或独立 ResNet 编码，本体向量直接保留，随后沿特征维拼接，并将最近 n_obs_steps 帧展平为全局条件 c。

  • 图像：高维、空间结构强，需要 CNN / SpatialSoftmax。
  • 本体状态：低维连续量，直接提供关节与末端状态。
  • 触觉扩展：源码未内置；可按触觉图像或触觉向量选择独立编码器，重点保证时间对齐和归一化。
面试表达

“多模态不是简单堆传感器，而是先解决各模态表示、时间同步和尺度统一，再形成可供生成模型调制的条件向量。”

GENERATIVE POLICY

策略学习条件动作分布，而不是唯一平均动作

行为数据经常一对多：面对同一场景，可以从左侧绕行，也可以从右侧绕行。直接 MSE 回归单一动作可能得到两种模式的平均；生成式策略额外引入随机变量，从同一条件下采样出不同但合理的整段动作。

ACTION CHUNKING

模型联合预测整段动作，控制器只执行其中一部分

Action Chunk 是形状为 [B, horizon, action_dim] 的动作轨迹。DiT 把每个动作时刻作为 token，通过 self-attention 联合建模；LeRobot policy 再截取从当前时刻开始的 n_action_steps 放入队列。

  • 优势：轨迹更平滑，减少模型调用，能表达长一点的操作结构。
  • 代价：连续执行期间不会重采样，环境变化可能造成开环误差。
  • 关键折中：n_action_steps 越小越闭环，越大越高效。

01

为什么用 Self-Attention？

每个动作时间步都能看到整段轨迹，适合学习跨时间的协调关系，而不是独立预测各步动作。

02

条件怎样进入网络？

t 与 c 相加后生成 shift、scale 和 gate，对归一化后的特征做自适应调制；源码没有使用 cross-attention。

03

为什么多处零初始化？

调制 gate 与最终输出层从零开始，使残差块初始更稳定，再逐渐学会由条件控制速度场。

SUPPORTING MODULES

主调用链之外，也要知道这些代码负责什么

下列模块篇幅较短，但共同保证时间表示、稳定初始化、模型构造和 LeRobot 接口闭环。

时间编码_TimeNetwork⌄ 
t = t[:, None] * self.w[None]
t = torch.cat((torch.cos(t), torch.sin(t)), dim=1)
return self.out_net(t)

用固定频率的 sin/cos 将标量 t 映射成高维表示，再由两层 MLP 投影到 hidden_dim。它告诉同一个速度网络当前处于生成路径的哪个阶段。

调制与门控_ShiftScaleMod / _ZeroScaleMod⌄ 
x = x * (1 + scale(c)) + shift(c)
gated_x = x * gate(c)

前者实现 adaptive shift/scale，后者控制注意力或 MLP 残差写入多少。线性层零初始化使训练开始时 gate≈0，减少深层 Transformer 的不稳定。

最终输出层_FinalLayer⌄ 
shift, scale = adaLN(cond + t).chunk(2, dim=1)
x = modulate(norm_final(x), shift, scale)
return linear(x)  # hidden_dim → action_dim

再次使用 t+c 调制 token，然后把每个 token 从隐藏维映射回动作维。该层参数整体零初始化，因此模型初始预测速度接近零。

模型构造DiTFlowModel.__init__⌄ 
global_cond_dim = state_dim + image_feature_dim * num_images

    ac_dim=action_dim, ac_chunk=horizon,

先按实际模态计算条件维度，再构造固定最大动作长度的速度网络；同时建立训练时间 t 的采样分布。

# 1. 多模态观测 → 条件向量 c
def encode_condition(state, images, rgb_encoder):
    B, S, N = images.shape[:3]
    image_feat = rgb_encoder(images.reshape(B*S*N, *images.shape[3:]))
    image_feat = image_feat.reshape(B, S, -1)
    return torch.cat([state, image_feat], dim=-1).flatten(1)

# 2. Flow Matching：回归直线路径的速度 a - ε
def flow_matching_loss(model, action, cond):
    B = action.shape[0]
    noise = torch.randn_like(action)
    t = torch.rand(B, device=action.device)
    t3 = t[:, None, None]

    x_t = (1 - t3) * noise + t3 * action
    target_velocity = action - noise
    pred_velocity = model(x_t, t, cond)
    return F.mse_loss(pred_velocity, target_velocity)

# 3. 推理：从噪声出发，用 Euler 法求解 ODE
@torch.no_grad()
def sample_action_chunk(model, cond, shape, steps=100):
    x = torch.randn(shape, device=cond.device)
    dt = 1.0 / steps
    for k in range(steps):
        t = torch.full((shape[0],), k / steps, device=cond.device)
        x = x + dt * model(x, t, cond)
        x = x.clamp(-1, 1)
    return x

# 4. horizon 从最早观测开始，只执行当前起的一段
actions = sample_action_chunk(model, cond, (B, horizon, action_dim))
start = n_obs_steps - 1
execute = actions[:, start : start + n_action_steps]

# 5. 部署时缓存动作；队列空了才重新生成
if len(action_queue) == 0:
    action_queue.extend(execute.transpose(0, 1))
action = action_queue.popleft()

轻量 CNN 提取空间特征；代码复用 Diffusion Policy 的 RGB encoder。

crop_shape84 × 84

11 · INTERVIEW KIT

高频追问与回答

Q1Flow Matching 和传统 Diffusion Policy 的核心区别是什么？⌄

二者都从噪声生成动作，但监督对象与生成动力学不同。这个实现构造噪声到数据的直线路径，直接回归速度 a−ε，推理时求解 ODE；典型 DDPM 路线常预测噪声或 score，并按预设噪声日程做反向去噪。面试中不要说 Flow Matching “完全不加噪声”，它训练时同样采样噪声和中间状态。

Q2为什么叫 DiT？Transformer 到底处理什么？⌄

它把动作序列中的每个时间步投影成一个 token，加可学习位置编码后送入 Transformer self-attention。流时间 t 与观测条件 c 不作为 token 拼进去，而是通过 AdaLN 的 shift、scale 和 gate 调制 block。

Q3为什么一次预测动作块，而不是一步一预测？⌄

动作块能联合建模跨时间相关性，使轨迹更平滑，也能摊薄 100 次 ODE 网络评估的成本。代价是开环执行期间反馈更新较慢，因此 n_action_steps 是响应速度、推理成本和动作连贯性的折中。

Q4horizon=16，为什么默认只执行 8 步？⌄

因为 horizon 从第一帧历史观测对应的时刻开始，而不是从当前时刻开始。n_obs_steps=2 时，索引 0 对应过去，当前动作从索引 1 开始；代码取 [1:9] 共 8 步，其余是上下文或未执行的未来预测。

Q5多相机图像如何融合？⌄

图像张量先组织为 [B,S,N,C,H,W]。默认所有相机共享一个 RGB encoder，先把 B、S、N 合并编码，再恢复 B、S 并把相机维吸收到特征维；也支持每个相机独立 encoder。随后与状态特征拼接并跨观测时间展平。

Q6动作为什么必须正确归一化？⌄

配置默认对 ACTION 使用 min-max 归一化，并在每个 Euler 步后裁剪到 [-1,1]。如果实际动作量纲没有映射到该范围，裁剪会改变物理含义。后处理器负责用数据集统计量反归一化回真实控制量。

Q7如果要加入触觉，应该从哪里改？⌄

保持 Flow Matching 主干不变，重点扩展输入 feature 与 _prepare_global_conditioning：为触觉图像复用或单设视觉 encoder；为触觉向量增加时序编码器，再与视觉、本体特征按观测步拼接。还需在 processor 中明确触觉归一化，并检查采样频率、时间对齐和缺帧处理。只是把触觉向量直接拼接也能运行，但未必充分建模接触的时序结构。

Q8如何降低推理延迟？⌄

优先评估减少 num_inference_steps 对成功率的影响；还可减小 hidden_dim / blocks、降低视觉分辨率、缓存不变视觉特征、使用更高阶 ODE solver 或蒸馏。增大 n_action_steps 能降低平均调用频率，但会牺牲闭环响应，不能只看吞吐。

12 · CRITICAL READING

能指出这些，说明你真的读过

以下是基于当前源码的工程审视，不影响理解其核心算法。

命名

NoiseNet 实际预测 velocity

类名 _DiTNoiseNet、变量名 eps_out 和部分注释沿用扩散噪声预测表述，但 loss 的监督明确是 trajectory − noise。解释代码时应以实际目标为准。

边界

仅环境状态路径需再检查

文档称可只使用 observation.environment_state，但 validate_features() 后续无条件读取第一项 image feature；若 image 列表为空会触发迭代结束异常。

一致性

use_proprioceptive=False 有维度风险

构造模型时可从条件维度中排除 robot state，但条件准备函数仍固定把 OBS_STATE 放入拼接列表，可能导致投影层输入维度不一致。

工程

仓库是插件，不是独立训练框架

pyproject.toml 没有声明核心 Python 依赖，运行依赖配套 LeRobot fork 与环境。复现时需要锁定兼容提交，而不能只执行一次通用 pip 安装。
